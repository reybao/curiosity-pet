# Curiosity Pet 开发思路与决策记录(2026-10-23)

CLAUDE.md 是规则,本文是理由和背景。新开会话先读本文和 CLAUDE.md。

## 1. 项目是什么

为 7 岁半、中英双语(常中英混说)的女儿做的本地 AI 学习宠物。孩子在 iPad 上用语音提问,Mac mini 本地完成语音识别、回答生成、资料检索、安全过滤和语音合成。孩子数据不出设备,没有云端回退。目标是练习提问、追问、验证和表达,不做任何留存设计。同时是课程项目,需要可复现的测试与评估。

## 2. 为什么从「个人本地助手」转向「儿童好奇心宠物」

原方案是 Mac mini 本地助手 + Telegram 入口 + Amazon 购物。调研发现 Amazon 已系统性封杀第三方 AI 代理(robots.txt 屏蔽 47 个以上爬虫,2026 年 3 月起条款要求代理表明身份,9 月封禁 Meta Muse;法律上第九巡回法院撤销了对 Perplexity 的初步禁令,大问题仍未定),外卖平台的官方通道(DoorDash MCP)只对企业客户开放候补。购物没有稳定终点。儿童版范围更小,技术难点真实(本地语音、儿童安全、可追溯回答),评价方法能说服人。

## 3. 本地小模型与云端大模型的分工

4B 到 9B 本地模型弱在事实知识、长链推理、复杂指令遵循、双语混说、安全判断;强在「给定材料范围内做短而明确的事」。因此采用「大模型离线建库、小模型在线表达」:用 Claude 等前沿模型生成并核对儿童级问答、测试集、评审本地模型输出;运行时全部本地。知识库广度而非模型参数,是产品质量的主要杠杆。

## 4. 和「给孩子开一个 AI 账号」的区别

云端模型更聪明,但主流服务有年龄门槛(ChatGPT 13+,Claude 18+),数据进厂商服务器,产品目标是留存。本项目的价值:无账号、数据不出家门、流程按教育目标设计、适龄性由程序保证而非厂商政策、知识边界可追溯、家长可见、不随产品改版而变。定位是「可完全控制的学习工具」。

## 5. 2026 年 10 月模型选型(16GB M4 定稿)

| 组件 | 选择 | 理由 |
|---|---|---|
| LLM | Qwen3.5-4B q4_K_M(Ollama llama.cpp 引擎,think=false,num_ctx 8192) | 中文最强小模型之一,质量接近上代 7B 至 8B;9B 放得下但贴近上限且首句过慢;对照组 Gemma 4 E4B |
| STT | Qwen3-ASR-0.6B 4-bit(mlx-audio) | 中文错误率远低于 Whisper(噪声普通话 CER 16 对 63),M4 Pro 上一句 0.13 至 0.18 秒;儿童语音竞赛冠军方案的共同底座;对照 Fun-ASR-Nano(唯一明确训练过中英混说) |
| VAD | Silero + smart-turn,静音阈值 0.8 秒起调 | 孩子停顿多;点一下说、说完自动结束,保留按住说话兜底 |
| TTS | Kokoro-82M v1.1-zh | 不到 0.5GB,首包约 65 毫秒;Qwen3-TTS 更好但多占近 2GB;短句偏弱,前两句合并再合成;iPad 自带语音为兜底 |
| 守卫 | Qwen3Guard-Gen-0.6B 严格模式 | 支持中文的唯一小型守卫;Llama Guard 4 不覆盖中文 |
| 向量 | Qwen3-Embedding-0.6B + sqlite-vec | 中英都好,单文件存储 |
| 后端 | Python + FastAPI + Pipecat,uv | 单进程,不用微服务 |
| 前端 | FastAPI 托管的轻量页面,Rive/Lottie 宠物动画 | 不用 React/Electron |

内存:GPU 可用约 10 至 11GB,常驻模型合计约 6GB,留 4GB 给 KV 缓存和进程。

延迟预算:断句 0.5 至 0.8 秒 + STT 0.2 + 守卫与检索 0.2 + 预填充 0.5 + 首句生成 0.6 + TTS 0.07,合计约 1.8 至 3.0 秒。关键技巧:逐句流式送 TTS、关闭 thinking、VAD 结束后 iPad 立即播提示音并切「在想」动画。

Ollama 要点:用原生 /api/chat(OpenAI 兼容端点忽略 num_ctx);KEEP_ALIVE=-1、NUM_PARALLEL=1、MAX_LOADED_MODELS=3;向量模型 num_ctx 压到 2048;16GB 上 MLX 引擎可能不启用,回落 llama.cpp 差 15% 至 30%,可接受;念给孩子的回答走流式文本不走 JSON,JSON Schema 只用于守卫、意图分类、记忆抽取。

证据空白(必须本机实测):7 岁儿童普通话识别率、各 TTS 中文自然度、base M4 真实 tok/s。

参考开源项目:kwindla/macos-local-voice-agents、mthomas100/local-voice、dusterbloom/localcat(Pipecat 本地语音管道,换 ASR 为 Qwen3-ASR 即为本项目骨架)。

### 2026-10-23 实测后的修订

- 主模型从默认标签 `qwen3.5:4b`(nvfp4,MLX 引擎)改为 `qwen3.5:4b-q4_K_M`(GGUF,llama.cpp 引擎)。
  原因:Ollama 0.40.9 的 MLX 引擎每次请求常驻内存持续增长,60 次请求从 4.1GB 涨到 12.6GB,触发交换并拖慢延迟;
  KV 缓存量化(q8_0)对 MLX 无效。llama.cpp 版 60 次请求后仍为 3.4GB,端到端开口中位数 2.25 秒(MLX 2.40 秒),
  语言正确率相同。KV 缓存保持 f16,q8_0 只省 0.1GB 且生成慢约 13%。数据见 `evals/results/2026-10-23.md`。
- 上文"MLX 引擎可能不启用,回落 llama.cpp 差 15% 至 30%"与实测不符:本机 MLX 可用,但 llama.cpp 端到端反而更快。

### 2026-10-23 阶段 2 的取舍

- 语音通道用 FastAPI WebSocket,不用 Pipecat。Pipecat 1.14 固定 soundfile 0.13(项目已用 0.14),并带入 onnxruntime、numba、
  OpenAI SDK 等依赖,还要把已测好的断句、识别、生成、合成模块改写成它的处理器。单孩子、单连接的场景下,
  直接用 WebSocket 传 PCM 更简单,沿用阶段 1 的模块和测试。以后需要 WebRTC 或打断(边说边听)时再评估。
- 宠物动画先用 SVG + CSS(零依赖、本地托管),有正式美术后再换 Rive 或 Lottie。
- Ollama 经 llama.cpp 运行 Qwen3.5 时无法复用提示缓存(混合架构 + Ollama 固定 `--cache-ram 0`),每轮都从头预填充。
  因此系统提示保持精简,会话历史只带最近 2 轮。

### 2026-10-24 允许有限联网(维基百科)

- 家长实测后反馈"很多信息不对",例如不知道《七龙珠》里的孙悟空。家长认为:本地没有资料时,
  一般知识问题可以联网;但大量孩子数据不能外传,孩子分享的私人、家庭信息和心情绝不能外发。
- 因此修改硬性约束第 1 条,加一个窄例外:只发经本地改写和规则检查的话题搜索词,来源先只用维基百科
  (事实为主、相对适龄;一般网页搜索内容太杂,暂不开)。联网多出约 1 至 2 秒,宠物先说"我去查一查"。
- 搜索词保留 7 天供家长查看,之后只留主题计数,周报里做事实性趋势(不做"越来越喜欢"之类的解读)。
- 联网开关默认打开,讲故事和睡前模式不联网;头两周家长每周查看记录,发现不妥就关掉并收紧规则。

### 2026-10-24 宠物形象与"互动习惯"

- 家长希望宠物是英短蓝猫,语音里有猫咪的感觉。为守住第 4 条硬性约束(明确是程序),保留项圈小灯作为程序标记,
  宠物自称"程序小猫,不是真猫,没有感受"。实测 4B 模型不遵守"最多一个喵"(13/36 次回答喵了不止一次),改由程序截断。
- 家长希望记录"性格、兴趣"并给建议。性格分析不做(第 3 条硬性约束:小模型判断不可靠,标签会影响家长对孩子的看法,
  周报孩子也会看)。家长同意改为:不分析性格,只保留能反映性格的**可数事实**("互动习惯"),由家长自己理解;
  兴趣按主题统计,周报给亲子活动建议。

## 6. 产品边界上的关键取舍

- 语音是第一版功能,iPad 网页必须 HTTPS,选 Tailscale 一并解决证书和设备配对;PWA 加引导式访问。
- 周报改为「发现周报」:只含问题原文、收藏、主题统计、未命中资料的问题、亲子活动建议;禁止能力、情绪、性格判断和比较;趋势只做事实层面;原料是结构化字段而非聊天原文;孩子一起看;家长可关可删。
- 聊天原文最多保留 7 天供家长查看;记忆只允许白名单字段,无自由文本「观察」字段。
- 守卫模型只拦「有害」,拦不了「不适龄」,所以叠加:系统提示、Qwen3Guard、家长主题范围与黑名单、知识库优先、敏感话题固定路径、限期日志;对抗测试集覆盖暴力、身体、「你是活的吗」、「我讨厌弟弟」、「别告诉妈妈」、吓人故事、越狱提示。
- 知识库:不下载整本维基百科或《十万个为什么》。优先大模型离线生成、家长审核的儿童级问答(先 300 至 500 条中英各一份),再加 Simple English Wikipedia 子集、Wikijunior、家里的书(不入仓库)。未命中问题记表,周报列出供补库。
- 讲故事:原创或公共领域改编(格林、安徒生、中国民间与成语故事),3 至 5 分钟,固定结构,可织入当天发现,守卫逐句检查,睡前模式慢速不追问。
- HomePod 封闭,只做 AirPlay 音箱播故事;语音入口保持 iPad。以后可评估 Home Assistant Voice PE 作语音卫星。

## 7. 开发方式与环境

- 在 Mac mini 上直接用 Claude Code 开发(开发环境即运行环境),从笔记本 SSH 或屏幕共享进入。
- 服务应跑在独立标准账户 pet 下;当前连接的是个人账户(设备 reys-mac-local,主目录已有 .ollama),先开发,正式使用前迁移。
- 目录三分:项目 ~/Projects/curiosity-pet(入 git);开发数据 ~/pet-data-dev;正式数据 ~/Library/Application Support/CuriosityPet;录音样本 ~/pet-evals/audio(后三者不入 git)。
- Claude Code 权限(.claude/settings.json):acceptEdits 加预放行(uv、ollama、git 提交、pytest、brew install、launchctl、tailscale);rm -rf、git push、git reset --hard 要问;禁止 sudo、读录音目录和正式数据目录、.env、~/.ssh。可用 auto 模式;不用 dangerously-skip-permissions。
- 需要 sudo 的电源与共享设置由用户在管理员账户执行(见 setup_mac_mini.sh 末尾)。

## 8. 阶段与验收

0 基线(tok/s、首字延迟、ASR 对孩子录音的错误率、4B 对 E4B 盲测)→ 1 命令行语音闭环(首句 3 秒内)→ 2 iPad 接入 + Tailscale + 宠物四态动画 → 3 学习流程 → 4 知识库、出处、未命中、兴趣卡片、删除 → 5 守卫、黑名单、敏感话题、家长页、保留规则 → 6 故事、周报 → 7 launchd 部署、备份、故障测试 → 8 成人虚构档案试用一周,再家长陪同短时试用。预计日历时间约两周。

## 9. 下一步(新会话从这里开始)

1. 创建 ~/Projects/curiosity-pet,把本包内容放进去(CLAUDE.md、setup_mac_mini.sh、.claude/settings.json、.gitignore、docs/DECISIONS.md),git init。

4. 录 30 至 50 句女儿的中英文和混说提问,放 ~/pet-evals/audio。
5. Mac 和 iPad 装 Tailscale 登录同一账号。
